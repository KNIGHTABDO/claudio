     no-build vanilla stack, drop Tailwind CDN for handcrafted CSS.

     Backend

     1. DB migrations — src/db.js (idempotent at startup)

     - messages + payload TEXT column (JSON: resolved tracks, ttsUrl, metadata)
     so chat history re-renders track cards after reload.
     - New station_state single-row table: queue JSON, current_index, position —
     restart resume.
     - New helpers: getLikes, getStats (play count, distinct genres etc.),
     saveStationState/loadStationState, payload-aware
     saveMessage/getRecentMessages.

     2. Server-authoritative queue — new src/station.js

     Singleton {queue, currentIndex, status, startedAt}; methods replaceQueue / 
     appendTracks / playIndex / next / prev / stop / onTrackEnded / snapshot.
     Every mutation persists (station_state) + broadcasts. Hydrates on boot.
     Fallback end-of-track timer (duration + grace) so dead client can't stall
     station.

     3. WS protocol redesign — server.js

     - Server→client: STATE (full snapshot on connect: station + chat history w/
     payloads), NOW_PLAYING, QUEUE_UPDATE, DJ_MESSAGE, USER_MESSAGE, LIKE_ACK,
     ERROR.
     - Client→server: CHAT, PLAY_INDEX, NEXT, PREV, STOP, PROGRESS (10s ticks),
     TRACK_ENDED. Heartbeat ping/pong, per-socket try/catch.
     - REST: keep GET /api/stream?v= untouched; add GET /api/state, GET 
     /api/profile (persona + taste.md genre pills + db stats + live listener
     count), GET /api/likes; keep POST /api/like; /api/history returns payloads.
     POST /api/chat retained but chat flows primarily over WS.

     4. src/router.js refactor

     Keep Groq→TTS→yt-search flow. Per-track try/catch during resolution; mutate
     station instead of returning client-owned queue; persist message payload.
     Scheduler (src/scheduler.js) routines flow through same DJ_MESSAGE path
     (drop DJ_ROUTINE).

     5. Cleanup

     Remove unused NCM_API_URL/JINA_API_KEY references from .env.example; keep
     src/claude.js Groq logic but tidy (strip existing comments too — whole
     codebase must end comment-free).

     Frontend rebuild — public/

     Files: index.html, styles.css, ES modules main.js, ws.js (reconnect +
     backoff), state.js (pubsub store), audio.js (music + TTS elements, ducking
     to 20%, progress), clock.js, ui/player.js, ui/queue.js, ui/chat.js,
     ui/profile.js, ui/theme.js. Delete old app.js, drop Tailwind CDN.

     Design system

     - CSS custom properties, data-theme="dark|light" on root, localStorage +
     prefers-color-scheme. Accent #22c55e, near-black bg, dotted-grid background
     layer, Space Mono + pixel display type, prefers-reduced-motion respected.

     Screens (per images-ref/ reference, then polish beyond)

     1. Header: "Claudio" pixel wordmark, DARK/LIGHT segmented toggle, profile
     button.
     2. Hero: huge dot-matrix clock rendered on canvas (5×7 dot glyphs, per-dot
     alpha tween on digit change, blinking colon, DPR-aware), day/date, ● ON 
     AIR.
     3. Player bar: animated EQ bars (freeze on pause), Title - Artist, PLAYING

     times.
     4. QUEUE panel: QUEUE / N TRACKS, numbered rows, artist right-aligned,
     current row green + ▶, click-to-play.
     5. Chat: ● Claudio LIVE bar, timestamps, DJ avatar messages, inline
     clickable track cards (active = green border + ★), user messages, input
     "Say something to the DJ..." with mic (browser SpeechRecognition,
     feature-detected) + send.
     6. Profile modal: avatar, pixel name, tagline, bio, stats ON AIR 24/7 /
     GENRES ∞ / LISTENER n, genre pills from taste.md, animated dot-wave.
     7. Footer status bar: CLAUDIO FM … CONNECTED bound to WS state.
     8. Boot screen replaces ignition overlay: dot-matrix PRESS TO START
